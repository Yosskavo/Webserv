00 Scope & state server.hpp

What the server owns

Scope

The whole server is one object. All mutable state lives in its member maps — there are no globals except the ignored SIGPIPE. Understand these five containers and the rest of the file is just moving fds between them.

The connection object — t_client

enum ClientState stateWhere this connection is: READING_HEADERS → READING_BODY → ROUTING → WRITING_RESPONSE → DEAD (plus WAITING_CGI).
std::string inbufRaw bytes received but not yet consumed. A request may arrive in pieces — this holds the partial.
t_request requestParsed method/target/headers + body handling (temp-file fd, chunked flag, content_length).
t_response responsestatus/headers/body, plus outbuf (serialized bytes) and bytes_sent (write cursor).
t_config* serverThe default virtual host for the listener this client arrived on.
t_location* locationThe matched location block — set during routing, drives every handler's paths.

The subprocess object — t_CgiProcess

pid_t pidChild process id; the key into the cgis map.
int out_fd / in_fdPipe ends the parent keeps to read the CGI's stdout (and, in principle, feed its stdin).
int client_fdWhich waiting client this output belongs to.
std::string outbufEverything the CGI has printed so far, accumulated until EOF.
bool stdin_closed / stdout_closedBoth true → the CGI is finished and gets reaped with waitpid.
01 init() server.cpp:75

Turn config blocks into listening sockets

Scope

Called once at startup. For each parsed server{} block, create/bind/listen a socket — but only one socket per unique ip:port, so several virtual hosts can share a port.

Logic

  1. Ignore SIGPIPE so a dead client can never crash the process.
  2. Build the (ip, port) key for this block.
  3. Already seen → append the config to that listener's vhost list; reuse the socket.
  4. New → socket → O_NONBLOCK → SO_REUSEADDR → bind → listen.
  5. Push a pollfd{fd, POLLIN} into listeners and record it in know_exist + servers.

02 run() server.cpp:988

The event loop — react, then reap

Scope

The heartbeat. Block on poll(), dispatch each ready fd by which map it belongs to, then clean up dead connections and finished CGIs in a separate pass.

Logic

  1. poll(-1) blocks until any fd is ready. EINTR → retry, other error → stop.
  2. For each ready fd, decide its type by map membership — listener (A), client (B), or CGI pipe (C).
  3. Clients handle error/read/hangup/write in that order; a WAITING_CGI client skips reads.
  4. Nothing is freed inside the sweep — dead things are only marked.
  5. After the sweep, reap: erase DEAD clients, waitpid finished CGIs.

03 accept_new_clients() server.cpp:116

Admit a new connection

Scope

A listener became readable. Accept the socket, make it non-blocking, register it in the poll set, and create a fresh t_client pointed at that listener's default vhost.

Logic

  1. accept() the pending connection; failure just logs and returns (loop continues).
  2. Set O_NONBLOCK — this client's reads/writes must never block the loop.
  3. Add a pollfd watching for POLLIN.
  4. Create the t_client at READING_HEADERS, defaulting to vhost [0].

04 handle_client_read() server.cpp:657

Read bytes, advance the state machine

Scope

Drives READING_HEADERS → READING_BODY → ROUTING in a single call. The stages use plain if (not else if), so one read can finish the headers and start the body in the same invocation.

A · receive into inbuf
B · READING_HEADERS — wait for the blank line
C · READING_BODY — chunked or content-length, streamed to a temp file

Logic

  1. recv once; EAGAIN → return, 0 or error → DEAD.
  2. In HEADERS: on \r\n\r\n, parse + pick vhost; POST → BODY, else → ROUTING.
  3. In BODY: open a /tmp file lazily so uploads never sit on the heap.
  4. Decode chunked sizes until the 0-chunk, or buffer to content_length.
  5. Enforce max_body continuously; overflow → 413. Body done → ROUTING → route().

Split the request line, headers, and pick the host

Scope

parse_request orchestrates the tokenizers (ft_method, ft_headers live under parce/) and flags chunked encoding. choose_server then selects the virtual host from the Host: header.

Logic

  1. Split the first line off; ft_method fills method/target/version.
  2. ft_headers parses the remaining key: value lines.
  3. If Transfer-Encoding: chunked, set is_chunked.
  4. choose_server strips :port from Host and matches a server_name.
  5. No match → keep the listener's default vhost.

06 route() server.cpp:607

The guard chain — decide what the request becomes

Scope

A sequence of early returns. Each guard either exits with a response or falls through to the next. The last guard dispatches by HTTP method.

Logic

  1. stat the target: a directory URL without a trailing / gets a 301 to target/.
  2. choose_location picks the longest matching prefix; none → 404.
  3. Method not in the location's bitmask → 405.
  4. A return directive short-circuits to a redirect.
  5. Extension mapped in cgi_ext → hand off to start_cgi.
  6. Otherwise dispatch to the GET / POST / DELETE handler.

07 choose_location() · is_method_allow() server.cpp:181 · 211

Longest-prefix match with real path boundaries

Scope

Pick the most specific location whose path is a prefix of the target — but only on a / boundary, so /foo never matches /foobar.

Logic

  1. Skip any location whose path isn't a prefix of the target.
  2. Accept only when it's an exact match or the next char is a / boundary.
  3. Among survivors, keep the longest path — the most specific rule wins.
  4. Methods are a bitmask; allow_method & GET tests one bit.

Remove a file

Scope

11 start_cgi() · build_env() server.cpp:296 · 248

fork, wire the pipes, execve the script

Scope

Spawn the CGI child with its stdout piped back to the server. The child's stdout pipe becomes a normal poll descriptor; the client parks in WAITING_CGI until EOF.

Logic

  1. Create the stdout pipe (and, for POST, a stdin pipe); pipe failure → 500.
  2. fork; failure → 500.
  3. Child: stdin ← body temp file (POST) or /dev/null (GET); stdout → pipe; execve.
  4. Parent: register std_out[0] in poll, record the t_CgiProcess.
  5. Client → WAITING_CGI; stop watching its socket until the CGI finishes.

Cases & environment

Watch: the POST std_in pipe is created but the child reads the body from the temp file, and the parent never closes std_in[0/1] → two fds leak per POST-CGI.

Collect CGI output, split its headers

Scope

Read the child's stdout non-blockingly into a buffer. On EOF, parse the CGI header block and turn it into the client's response.

Logic

  2. read < 0 (not EAGAIN) → clean up, 502.
  3. read > 0 → append to outbuf, come back next event.

  5. Parse fails → 502; success → build response, arm POLLOUT.

13 build_response() · handle_client_write() server.cpp:933 · 958

Serialize once, drain with a cursor

Scope

Every response funnels through one serializer into outbuf, then one writer sends it, advancing bytes_sent so partial writes resume cleanly across POLLOUT events.

Logic

  1. Write the status line, then Content-Length, a default Content-Type, and Connection.
  2. Emit every header, a blank line, then the body — into outbuf.
  3. The writer sends from bytes_sent onward; a short write just advances the cursor.
  4. Fully sent + keep-alive → reset_client, re-arm POLLIN.
  5. Fully sent + close → mark DEAD.

Error pages, teardown, and connection reuse

Scope

Shared exits: build an error response (custom page or generated HTML), tear a dead connection down completely, or reset one for the next request on a kept-alive socket.

Logic

  1. queue_error: a configured error_page is served as a file; otherwise a small HTML page is generated.
  2. Both paths end at WRITING_RESPONSE with POLLOUT armed.
  3. cleaning_client: drain the socket, close/unlink the body temp file, close the fd, drop it from listeners and clients.
  4. reset_client: free body state and reset request/response back to READING_HEADERS.
